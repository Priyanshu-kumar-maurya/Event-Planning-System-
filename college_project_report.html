ABSTRACT

In contemporary academic campuses, organizing, publicizing, and participating in college events — ranging from technical hackathons, cultural festivals, sports tournaments to entrepreneurial summits — is frequently hampered by fragmented communication channels, manual paper registrations, lack of real-time seat tracking, and absence of unified attendee management for organizers.

The Event Planning System (EventHub) is an enterprise-grade full-stack web application architected using the MERN (MongoDB, Express.js, React.js, Node.js) stack to streamline college event management into an automated, real-time, paperless ecosystem. The system features:

  • Role-Based Authentication: Secure user authentication using bcrypt password hashing and JSON Web Tokens (JWT), segregating standard student users from college administrative authorities.
  • Live MongoDB Event Inventory: Real-time event discovery with debounced keyword search, category filtering, and sorting capabilities.
  • Strict Registration Guard: Intelligent prevention of unauthenticated participation and duplicate registrations, backed by automatic seat quota decrement and waitlist computation.
  • Event Creation & Live Preview Studio: Comprehensive event publication form with live card preview, future-date enforcement (preventing past date scheduling), and universal media support (including automated Instagram post conversion, Google Drive sharing, and CDN images).
  • Dynamic Event Modification: In-place event timing, venue, capacity, and detail editing accessible to creators and administrators.
  • Administrative Intelligence & CSV Export: Real-time platform analytics, student directory, event inventory control, and 1-click attendee roster CSV generation for campus administration.
  • Ultra-Responsive Glassmorphism Interface: Dark purple theme optimized for mobile smartphones, tablets, and desktop displays with touch-friendly controls.

The application has been deployed on cloud infrastructure (Vercel serverless environment with MongoDB Atlas), offering instantaneous accessibility to students and college coordinators.

Chapter 1: Introduction

1.1 Background

Higher education institutions thrive on extracurricular and co-curricular vitality. Throughout any academic semester, colleges and universities host a wide spectrum of events including technical symposiums, hackathons, robotics competitions, cultural evenings, debating tournaments, inter-college athletic meets, and enterprise summits. These events play a pivotal role in nurturing leadership, technological aptitude, cultural appreciation, and interpersonal collaboration among students.

However, the administrative overhead required to plan, promote, register, and coordinate such events has conventionally relied upon obsolete manual modalities. Event flyers circulated on notice boards or scattered messaging groups fail to provide comprehensive agendas, transparent seat limits, or verified attendee rosters. As student populations in contemporary educational establishments expand into thousands, the absence of an integrated, automated software framework leads to systemic chaos, registration collisions, poor student turnout, and unaccountable administration.

1.2 Problem Statement

The core problem addressed in this project is the absence of a unified, real-time digital platform tailored for college campuses that enables students to discover upcoming activities, allows society coordinators to publish and modify events with live previews, prevents unauthorized registrations, and equips administrative personnel with instant analytic reporting and attendee auditing.

1.3 Proposed System (EventHub)

To overcome these systemic shortcomings, the Event Planning System (EventHub) is developed as a modern, reactive single-page web application (SPA) integrated with a high-throughput NoSQL document database. EventHub provides students with an intuitive portal to explore events categorized by domain (Technology, Cultural, Sports, Business, Art, Music, Food), register with automated credential binding, monitor personal registrations, and create student-led club events.

Simultaneously, administrators are granted privileged oversight into platform metrics, attendee contact records, and automated CSV export capabilities, establishing an end-to-end, paperless operational pipeline.

Chapter 2: Limitation of Existing System

Prior to the development of the automated Event Planning System, universities and colleges predominantly leveraged conventional approaches such as Google Forms, paper registration slips, WhatsApp broadcast messages, and static notice boards. A critical analysis of these mechanisms reveals numerous operational and security limitations:

  1. Lack of Real-Time Seat Synchronization: Conventional Google Forms or manual registers cannot dynamically enforce maximum seating limits. If an auditorium accommodates 200 participants, forms frequently continue accepting entries beyond capacity, leading to severe overbooking, seat disputes, and embarrassment for the organizing committee.
  2. Zero Authentication & Spam Entries: In existing Google Form links shared across social media, any person can submit arbitrary, fake, or duplicate entries using anonymous email addresses without verification. There is no cryptographic authentication verifying whether the registrant is a genuine enrolled student.
  3. No Unified Schedule & Central Repository: Information regarding different college societies (e.g., Coding Club, Dance Society, Sports Council) is siloed across disparate Instagram pages and WhatsApp channels. Students frequently miss registration deadlines due to lack of a centralized campus calendar.
  4. Absence of Dynamic Event Modification: If an event's schedule, timing, or venue changes (e.g., rain forcing an outdoor event into an indoor seminar hall), existing posters and shared messages cannot be updated dynamically. Students remain unaware of rescheduling, resulting in disorientation.
  5. Manual Attendee Verification & Audit Challenges: Faculty coordinators must manually stitch together multiple spreadsheets to prepare attendee lists. Exporting verified rosters with phone numbers, student college names, and timestamps is arduous and prone to human error.
  6. Poor Mobile User Experience: Traditional forms and college portals lack responsive glassmorphism interfaces, forcing students on smartphones to pinch, zoom, and navigate clunky desktop views.

Chapter 3: Objectives

The primary objective of developing the Event Planning System (EventHub) is to engineer a dependable, scalable, and responsive web application that digitizes campus event management. The specific objectives of the project are:

  • Automated Real-Time Registration: Implement an instant 1-click registration mechanism that records attendee profile details (name, email, phone, college) into MongoDB and automatically increments participant counts while updating seat availability indicators.
  • Strict Authentication & Role-Based Access Control (RBAC): Establish a secure security boundary utilizing JSON Web Tokens (JWT) and bcrypt password encryption, ensuring unauthenticated visitors cannot register for events and distinguishing Student users from College Administrators.
  • Dynamic Event Creation & Live Card Preview Studio: Provide authorized student organizers with a structured multi-section event creation studio featuring real-time previewing, tag assignment, price configuration, and custom media binding.
  • Validation Guard against Past Date Scheduling: Enforce calendar validation constraints prohibiting organizers from scheduling events with past dates, ensuring only current and future events are permitted.
  • Universal Media & Social Link Normalization: Implement automatic link transformation supporting Instagram post URLs (extracting high-resolution media), Google Drive public shares, and CDN images with no-referrer policies and automatic category fallbacks.
  • Event Schedule & Venue Modification: Deliver full lifecycle event editing allowing organizers and administrators to adjust event dates, start/end times, venue rooms, and descriptions with automatic database synchronization.
  • Administrative Roster Management & 1-Click CSV Export: Provide college administration with real-time statistics (total hosted events, aggregate registrations, registered students, estimated revenue) alongside instantaneous CSV file generation for offline verification and certificate generation.

Chapter 4: Scope

4.1 Functional Scope

The functional scope encompasses all operational modules, interactions, and business rules executed by the system:

  • User Management Module: Registration, login, profile identification, encrypted token storage in browser local storage, and automated session renewal.
  • Event Catalog & Exploration Module: Live search debounced at 300ms, multi-category pill filter (All, Technology, Cultural, Sports, Business, Art, Music, Food), and multi-criteria sorting (Date, Popularity, Free First, Newest).
  • Registration & Capacity Enforcement Module: Enforces login before registration; displays real-time percentage capacity fill bars; blocks registration when seats reach capacity; prevents duplicate participation.
  • Event Creation & Modification Module: Input fields for Title, Category, Date, Time, Venue, Seats, Price, Image URL, Tags; live sticky card preview; date picker locked to min=Today; in-place edit capability for event creators and admins.
  • Student Dashboard Module: Segregated tabs displaying "Events You Registered For" with 1-click unregister, and "Events You Organized" with quick edit and delete actions.
  • Admin Dashboard Module: Comprehensive metrics dashboard, searchable event inventory, per-event attendee directories, registered user roster, and automated browser-side CSV export generator.

4.2 Technical Scope

The technical architecture adheres to contemporary web engineering practices:

  • Client-Side Architecture: Developed using React 18, utilizing functional components, custom hooks, and context API (AuthContext) for global state management without external heavy libraries.
  • Build Optimization: Powered by Vite build tool providing sub-second Hot Module Replacement (HMR) and roll-up production minification.
  • Server-Side Architecture: RESTful API engine powered by Node.js and Express.js, featuring modular routing (authRoutes, eventRoutes) and centralized error handling middleware.
  • Database Architecture: Hosted on MongoDB NoSQL database utilizing Mongoose Object Data Modeling (ODM) with embedded sub-documents for registered attendees.
  • Security Infrastructure: JWT bearer tokens, bcrypt hashing (10 salt rounds), CORS whitelisting, and input sanitization.

Chapter 6: Advantages

Implementing the Event Planning System offers substantial operational, administrative, and ecological benefits over legacy methodologies:

  1. Zero Overbooking with Automated Seat Locks: The platform dynamically monitors attendee counts against declared capacity. Once spots are exhausted, the registration button automatically transitions to a disabled "Event Full" state, preventing seat collisions.
  2. 100% Paperless and Eco-Friendly: Eliminates physical registration desks, paper forms, and printed ticket stubs. All records, registrations, and verification lists reside securely in digital storage.
  3. Instant Administrative Reporting (CSV Generation): Campus authorities can download comprehensive attendee lists containing student names, contact numbers, email addresses, and timestamps with a single click, saving hours of manual consolidation.
  4. Universal Social Media Image Integration: Organizers can directly paste Instagram post links, Google Drive photo links, or Unsplash URLs without needing to re-upload files to expensive third-party storage buckets.
  5. Responsive Multi-Device Usability: Crafted with a mobile-first philosophy, students can browse events, register, or review schedules on Android/iOS smartphones just as smoothly as on desktop monitors.
  6. Robust Security & Privacy: Sensitive user passwords are encrypted with one-way bcrypt hashing before database persistence. JWT tokens ensure users can only modify or delete events they legitimately organized.
